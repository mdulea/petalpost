# Guest lists with personal links

When publishing, the host chooses the open mode or the guest-list mode. The open mode is the default and works as before. Any guest with the invitation link can reply, and each reply gets a reply edit link. In the guest-list mode, the invitation link shows the invitation without a reply form. A guest replies only through the personal link of their party. A forwarded invitation link then adds no uninvited replies, and the host sees who has not replied yet. The open mode stays the default so that a casual party keeps one link and needs no guest list.

The unit of a guest list is the party, such as "Familia Popescu", and not each person. A party has one personal link and at most one reply. Hosts invite families and couples together, and one person usually replies for all of them. Names for each person would make the host type every child's name and make the guest answer for each one. In exchange, the host cannot record a meal choice per person or split a party across tables.

Each party also has a view link. It shows the same invitation without the reply form or the reply. A guest can show the invitation to a friend, and the friend cannot read or change the reply. Regenerating a party's personal link replaces its view link too, so a link forwarded through either one stops working. The reply stays on the party, so the guest with the new link sees their earlier reply.

The host gives each party a default number of seats, and a guest can reply with more, up to 20. The tracker marks the party "over by N" and counts the extra seats in the totals. A hard limit would make a guest with an uncounted partner or child call the host instead of replying. The soft default keeps the real number in the totals and shows the host each change to follow up.

A guest-list invitation needs an event date. Its guest list and replies are deleted at 23:59 Europe/Bucharest time on the day after the last sub-event. Afterwards every link and the tracker show "This invitation has ended". The open mode keeps its 90-day rule. A guest list holds names the host typed about other people, so the server keeps them only while the host needs them. The extra day covers late changes on the day of the event. After the deletion the host cannot download the CSV, so the tracker warns before it.

The host returns to the tracker without an account. Three ways lead back: "My invitations" in each browser that opened the tracker, a tracker link the host sent to themselves, and a passkey saved for the invitation. Before this decision, the management link was the host's only way back, and a host who lost it lost the replies. An account would break the promise that hosts and guests need no account and no email address. The wedding planners surveyed in #99 all require one. A passkey syncs only inside one platform account, such as iCloud Keychain, so a host who moves between platforms relies on the link they sent to themselves. A co-host gets the same tracker link and has no separate rights or revocation.
